Welcome

This website is the WVU instructor and staff handbook for deploying the xPostForecast full-stack application from local development to Microsoft Azure cloud hosting.

It reorganizes the project's README files into a single step-by-step flow so a professor can go from initial setup through final production validation, and it adds the instructor-only steps (provisioning Azure resources each semester) that the student guides leave out.

WVU note: For WVU courses, resource groups are not self-created by project teams. Submit a request to Statler ITS to have resource groups created or updated.

How to use this documentation

If you are new to cloud deployment support, follow these pages in order. Each page explains what to verify, why the step matters, and what success should look like before moving to the next stage.

  1. Read Getting Started for prerequisites and required access.
  2. Use GitHub Setup to configure repo workflows and secrets.
  3. Use Azure Basics to confirm Azure resources and settings.
  4. Follow Deployment Steps from first local run to production, including the per-semester setup checklist.
  5. Use Troubleshooting for common errors and quick fixes.

How the course repository is organized

xPostForecast keeps each sprint on its own branch, with the app's frontend/ and backend/ folders at the top level of every branch:

BranchSprintAdds
sprint-11React (Vite) frontend: Leaflet map and month/year selector
sprint-22Express backend, Azure MySQL, login with JWT cookies
sprint-33NOAA temperature data from the Planetary Computer STAC API
main4Deployment to Azure with GitHub Actions; also holds this site in docs/

GitHub's compare view shows exactly what each sprint changed, for example sprint-2...sprint-3.

What these guides cover

  • Local project setup with Vite, React, Node.js, Express, and MySQL.
  • Authentication with JWT in HTTP-only cookies and protected routes.
  • Azure MySQL connection using a CA certificate and environment variables.
  • STAC climate data integration through Microsoft Planetary Computer APIs.
  • Cloud deployment via Azure App Service, Azure Static Web Apps, and GitHub Actions.
  • Validation steps, health checks, and production troubleshooting.

This site is published with GitHub Pages from the docs/ folder of the main branch. Update it in the same commit as any code change it describes.
