Troubleshooting

This page centralizes common errors from the project READMEs and gives immediate checks and fixes for staff supporting course teams.

Authentication and CORS Issues

If login behavior seems inconsistent, start here first. Cookie handling and cross-origin configuration are the most common causes of "works locally, fails in cloud" behavior.

Symptom Likely Cause Fix
401 from /auth/test in the browser console Not logged in Expected before login and after logout.
Locally: login succeeds but a refresh logs the user out Credentials not sent with requests Use withCredentials: true (axios; the shared src/api.js sets it) or credentials: 'include' (fetch).
On Azure: login returns 200, then every request is 401 Cookie not sent cross-site Set NODE_ENV=production on the App Service so the cookie is SameSite=None; Secure; Partitioned. If it works in one browser but not another, that browser blocks cross-site cookies.
CORS error mentioning Access-Control-Allow-Origin FRONTEND_URL doesn't match the frontend's address Set it to the exact origin (http://localhost:5173 locally, the SWA URL on Azure), no trailing slash.
404 for /login from the backend Missing auth route prefix Call /auth/login and /auth/register.
409 on register Username or email already exists Use another, or delete the row in MySQL.
429 Too Many Requests Login/register rate limit (20 per IP per 15 minutes) Wait, or restart the backend (the counter is in memory).

Database and TLS Issues

Database errors often look like application failures. Validate the certificate path, credentials, and network access before changing route or UI code.

Symptom Likely Cause Fix
Missing required environment variables: … at startup .env (local) or App Service setting (Azure) missing or misspelled Add the listed variables with the exact names from backend/.env.example.
ER_BAD_DB_ERROR: Unknown database Schema not created Run backend/db/schema.sql.
MySQL TLS connection failure Missing or wrong CA certificate Use the certificate downloaded from the server's Networking page, at backend/config/DigiCertGlobalRootG2.crt.pem.
connect ETIMEDOUT to MySQL on Azure Server networking doesn't allow Azure services Enable "Allow public access from any Azure service" on the MySQL server, or escalate to WVU cloud support.
Cannot connect from local tools Client IP not allowed Add or update the Azure MySQL firewall rule for your public IP.

GitHub Actions and Deployment Issues

Pipeline failures are usually path, test, or secret mismatches. The deploy workflows check their secrets first and name anything missing in the log.

Symptom Likely Cause Fix
… is not set in the "Check repository settings" step Missing secret or variable Add it under Settings → Secrets and variables → Actions (names are case-sensitive).
Workflow cannot find the backend or frontend directory Path doesn't match the repo layout Use backend / frontend (top-level folders) in working-directory, cache path, and package path.
Workflow fails at the test step A failing test, or npm's default placeholder test script Run npm test locally and fix it; don't disable the step.
Download publish profile is greyed out SCM basic-auth publishing disabled App Service → Configuration → General settings → SCM Basic Auth Publishing Credentials: On.
Deployed site calls undefined/auth/...; console shows Frontend API Base URL: undefined VITE_BACKEND_API_URL not given to the build Add the secret, and in an Azure-generated workflow map it in the deploy step's env:.
404 when refreshing /map on the deployed site No navigation fallback Add frontend/public/staticwebapp.config.json.
Every push deploys the frontend twice An Azure-generated workflow and a custom one both deploy Keep only one.
SWA YAML validation warning in close PR job Missing app_location in close job config Add the same app_location value as the main deploy job.

Data (Temperature Map) Issues

  • 404 No temperature data is available for …: Planetary Computer's copy of nClimGrid covers January 1895 through September 2022.
  • 502 from /temperature/…: Planetary Computer was unreachable; the log stream shows the underlying error. Retry later.
  • The first request for a month takes several seconds; repeats are fast because the backend caches each month.

App Service Runtime Issues

  • If the backend does not start on Azure, read the first error in the log stream; the app listens on process.env.PORT automatically.
  • If the health endpoint fails, confirm the environment variables were applied and the app restarted.
  • If /health shows "env": "development", NODE_ENV is not set to production.
  • Use App Service Log Stream while restarting the app to capture startup errors immediately.

Fast Triage Workflow for Staff

  1. Check GitHub Actions status for the latest CI, backend, and frontend runs.
  2. Validate the backend health endpoint in the browser.
  3. Open browser dev tools: the console's Frontend API Base URL and the Network tab show which backend the frontend calls.
  4. Review the App Service log stream for startup, CORS, and database errors.
  5. If a resource or network-level issue is suspected, escalate through the WVU support process.
Escalation note: When missing resource groups or restricted cloud access blocks progress, route the request to Statler ITS.
