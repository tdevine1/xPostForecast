Azure scripts

Setting up ten team resource groups by clicking through the portal is slow and error-prone. These PowerShell scripts do the repetitive parts for every group at once: servers, backends, frontends, access, and end-of-semester cleanup. Run them from your own computer or from Azure Cloud Shell.

New to scripts? A script is a text file of commands that a computer runs in order, so you type one line instead of clicking through the portal ten times. These ones are written in PowerShell, which is built into Windows. Nothing here changes anything until you run it, and every script has a safe "pretend" mode (-WhatIf). Unfamiliar words are in the Glossary.

Resource groups come first. For WVU courses, request them through Statler ITS. The scripts create resources inside resource groups that already exist and skip any that don't.

Running a script, step by step

Choose one of the two places to run them. Cloud Shell is easiest the first time because the sign-in and tools are already set up.

Option 1: Azure Cloud Shell (no installs)

  1. In the Azure portal click the >_ icon at the top, and choose PowerShell if asked.
  2. Click Manage files → Upload and pick the .ps1 file you downloaded.
  3. Run it with a leading ./, adding -WhatIf the first time: 
    ./New-GroupStaticWebApps.ps1 -Semester 202608 -Crn 84715 -LastGroup 10 -WhatIf

Option 2: Your own computer

  1. Do the "Before you run anything" steps below once (install the tools, sign in).
  2. Open Windows PowerShell from the Start menu and move to the folder that holds the script, for example cd $HOME\Downloads.
  3. Unblock it and run it, adding -WhatIf the first time: 
    Unblock-File .\New-GroupStaticWebApps.ps1
.\New-GroupStaticWebApps.ps1 -Semester 202608 -Crn 84715 -LastGroup 10 -WhatIf

Reading the result of -WhatIf: lines starting What if: are things the script would do. Nothing has happened yet. If the list is what you expect, run the same command again without -WhatIf. If a group is skipped with a warning that its resource group "does not exist", check the term code, section, and CRN you typed.

Before you run anything

  1. Install the Az PowerShell module once (Cloud Shell already has it): 
    Install-Module Az -Scope CurrentUser

    PowerShell may ask whether to trust the online repository: answer Y (or A for "yes to all"). It takes several minutes. Check it worked with Get-Module Az -ListAvailable | Select-Object -First 1 Name, Version, which should print a version number.

  2. Install the Azure CLI. Only New-GroupAppServices.ps1 uses it (Cloud Shell has it too).
  3. Sign in. These are two separate sign-ins: Connect-AzAccount does not sign in the CLI. 
    Connect-AzAccount
az login
Select-AzSubscription -Subscription "<subscription name or id>"
az account set --subscription "<subscription name or id>"

    The course subscription is named ind-statler-mhseery.

  4. Windows blocks scripts downloaded from the web. After downloading, run Unblock-File .\<script>.ps1 and, if needed, Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.
  5. Always run with -WhatIf first. Every script supports it and prints what it would do without changing anything.

The semester in order

These scripts create billable resources. Running the MySQL and App Service scripts for ten groups creates ten database servers and ten plans, and they cost money by the hour until they are deleted. Run each with -WhatIf first, and remove everything at the end of the semester with the Remove script.

New-GroupMySqlServers.ps1

Creates <group>-mysql-db in each existing group resource group, as the mysqladmin user.

.\New-GroupMySqlServers.ps1 -Semester 202608 -Crn 84715 -LastGroup 10 -WhatIf
.\New-GroupMySqlServers.ps1 -Semester 202608 -Crn 84715 -LastGroup 10
  • You are prompted for the administrator password (typing is hidden). It is never stored in the script. Pass -AdminPassword (a SecureString) to skip the prompt.
  • Use a new password each semester and don't build it from a pattern: anyone who learns the pattern knows every semester's password.
  • Defaults: region eastus, size Standard_B1ms. Keep the database in the same region as the backend.
  • Afterwards, for each server: allow access from Azure services, add student IPs, and create authdb and the schema (see Deployment Steps and Azure Basics).

New-GroupAppServices.ps1

Uses the Azure CLI to create a Linux plan, a Node 24 LTS web app on it, and turns on publish-profile access.

.\New-GroupAppServices.ps1 -Semester 202608 -Crn 84715 -LastGroup 10 -WhatIf
.\New-GroupAppServices.ps1 -Semester 202608 -Crn 84715 -LastGroup 10

# One named group (for example the demo), reusing a plan that already exists:
.\New-GroupAppServices.ps1 -ResourceGroupName 202608-CS330-001-84715-DEMO -PlanName <existing-plan>
  • Plain host names. Apps created with the CLI get <name>.azurewebsites.net. The portal's create form adds a random suffix and region to the host name, which breaks every doc that assumes a plain one.
  • Publish-profile access. New apps have SCM basic authentication switched off, which greys out Download publish profile. The script switches it on, as the runbook requires.
  • Cost. The default plan is B1, the cheapest Basic tier. The portal's create form defaults to a much larger Premium plan, so check the size if you create plans by hand. A plan is billed while it exists, even with no app on it, so delete unused plans.
  • Runtime. Defaults to NODE:24-lts to match the workflows. See what is currently offered with az webapp list-runtimes --os linux.

New-GroupStaticWebApps.ps1

Creates <group>-frontend without connecting a repository. Teams connect their own, or deploy with their workflow and the app's deployment token.

.\New-GroupStaticWebApps.ps1 -Semester 202608 -Crn 84715 -LastGroup 10 -WhatIf
.\New-GroupStaticWebApps.ps1 -Semester 202608 -Crn 84715 -LastGroup 10
  • Free by default. -SkuName Standard is a paid plan and is only used if you ask for it. The portal's create form defaults to Standard.

Add-UsersToResourceGroup.ps1

Gives people a role (default Contributor) on one resource group, after looking each person up in Microsoft Entra ID. Run it once per team.

.\Add-UsersToResourceGroup.ps1 -ResourceGroupName 202608-CS330-001-84715-Group01 -EmailsFile .\group01.txt -WhatIf
  • The e-mail file has one address per line; blank lines and lines starting with # are ignored. Start from students.example.txt.
  • Keep the e-mail file out of Git. Student addresses are personal data. The script reads them from a file you control, so none are stored in the script or on this site.
  • People who already have the role are skipped, so you can re-run it safely. Use -Role for something narrower than Contributor.

Remove-GroupResourceGroups.ps1

Deletes a semester's resource groups, and everything inside them, so the class stops costing money. A resource group is a folder of Azure resources; deleting it deletes every resource in it: the MySQL servers with all their data, the App Service plans, the web apps, and the Static Web Apps. The resource groups themselves go too, so Statler ITS has to create them again next semester. This cannot be undone.

.\Remove-GroupResourceGroups.ps1 -Semester 202608 -Crn 84715 -LastGroup 10 -WhatIf
.\Remove-GroupResourceGroups.ps1 -Semester 202608 -Crn 84715 -LastGroup 10
  • You must give the semester and CRN: nothing is hardcoded, so it can't act on last term's names by accident.
  • It prints every resource group that exists and every resource inside it, by name and type, so you can see exactly what will go. Then it asks you to type the semester code before deleting anything.
  • The DEMO resource group is deleted too. Add -ExcludeDemo to keep it.
  • After deleting, set DEPLOY_TO_AZURE to false and remove the old secrets in the reference repository (see Deployment Steps).

Troubleshooting

SymptomLikely causeFix
az commands fail with "Please run 'az login'" after Connect-AzAccount worked The CLI and Az PowerShell have separate sign-ins Run az login and az account set --subscription ...
"Resource group ... does not exist. Skipping." Wrong semester, section, or CRN, or the group isn't created yet Check the names in the portal, or request the group from Statler ITS
"File ... cannot be loaded because running scripts is disabled" PowerShell execution policy, or a downloaded (blocked) file Unblock-File the script; Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
"Download publish profile" is greyed out on a backend SCM basic authentication is off (the default for new apps) Turn it on under Settings → Configuration → General settings, or run the az resource update command from New-GroupAppServices.ps1 for that app
A user is "not found in Entra ID" Typo in the address, or the person is a guest with a different sign-in name Check the address in Entra ID and use the exact user principal name
