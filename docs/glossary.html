If a word is new, look here

Cloud computing has a lot of vocabulary, and the guides use it from the first page. Each entry says what the thing is, using an everyday comparison where one helps, and where you will meet it in this course. Nobody expects you to know these words already.

Azure terms

Azure is Microsoft's cloud: computers, storage, and databases you rent by the hour instead of owning.

TermWhat it meansWhere you see it
SubscriptionThe billing account that Azure charges for everything you create. Think of it as the credit card tab the resources run up.The WVU course subscription is ind-statler-mhseery.
Microsoft Entra IDWVU's sign-in directory (it used to be called Azure Active Directory). Azure looks people up here by e-mail address when you give them access.The Add-UsersToResourceGroup.ps1 script.
Contributor (role)A permission level on a resource group: the person can create, change, and delete the resources in it, but can't give other people access. It is what a team needs to configure its own app.Access control (IAM) on a resource group.
Resource groupA folder that holds one team's Azure resources. Deleting the folder deletes everything inside it, which is how a semester is cleaned up. WVU's Statler ITS creates these for us.202608-CS330-001-84715-Group01
RegionThe physical place Azure's computers are. Resources that talk to each other work best in the same region.East US for the database and backend.
SKU / tier / pricing planThe size and price level of a resource, such as Free, Basic, or Premium. Bigger costs more, every hour it exists.Backend plan Basic B1; Static Web App Free.
App Service planThe rented computer that web apps run on. You are billed for it while it exists, even if no app is on it. Several apps can share one plan.ASP-…-a773
App Service (web app)Your program, running on an App Service plan. In this project it is the Node.js backend.202608-cs330-demo-backend
Static Web App (SWA)Hosting for website files that are already built (HTML, JavaScript, CSS). It runs no server code of its own, so it can be free.Hosts the React frontend.
Azure Database for MySQL Flexible ServerA MySQL database that Azure runs and backs up for you. It stores the users table.xpostforecast-db
SchemaThe blueprint of a database: which tables exist and what columns they have. Our schema is one users table, created by running backend/db/schema.sql once.The "create the table" step of the runbook.
Firewall ruleAn allow-list of internet addresses (IPs) that may connect to the database. If your address isn't on it, the connection times out.MySQL server → Networking.
TLS and CA certificateTLS is the encryption that protects data travelling between two computers (the padlock in a browser uses it). A CA certificate is the public file a program uses to check it is really talking to Azure's server and not an impostor. The certificate is public, not secret.backend/config/DigiCertGlobalRootG2.crt.pem
Publish profileA small file of login details for one App Service. GitHub uses it to upload new code. Treat it like a password.App Service → Overview → Download publish profile.
SCM basic authenticationA setting on an App Service that allows publishing with a username and password (which the publish profile contains). New apps have it off, which greys out Download publish profile.Created off; the runbook turns it on.
Deployment tokenThe password GitHub uses to upload a website to one Static Web App.Static Web App → Manage deployment token.
Application settings (environment variables)Values your program reads when it starts, such as the database address. They live in Azure, not in your code, so secrets never go into GitHub.App Service → Settings → Environment variables.
Default domain (host name)The web address Azure gives an app. Apps created in the portal get a random-looking suffix; apps created with the command line get a plain one. Always copy it from the Overview page; never guess it.202608-cs330-demo-backend.azurewebsites.net
Cold startThe first request after a deploy or a quiet period is slow (a minute or more) while the app wakes up. After that it answers in a fraction of a second.Your first /health check.
Always OnAn App Service setting that keeps the app awake so the first visitor doesn't wait through a cold start. It is available on Basic plans and above (not Free), and costs nothing extra on a plan you already pay for.App Service → Settings → Configuration → General settings.
Log streamA live feed of what your running app is printing, like watching the app's diary being written. It is where startup and database errors show up.App Service → Monitoring → Log stream.
Cloud ShellA command line that runs inside the Azure portal, already signed in, with the Azure tools installed. Click the >_ icon at the top.Creating the database schema; running az commands.
Azure CLI (az) and Az PowerShellTwo different command-line tools for Azure. They sign in separately: az login for the first, Connect-AzAccount for the second.The scripts on the Azure Scripts page.
Terminal and PowerShellA terminal is a window where you type commands instead of clicking. PowerShell is the command language built into Windows. In VS Code, open one with Terminal → New Terminal.Every guide that shows a code box of commands.
-WhatIfA switch you add to a PowerShell command to mean "pretend": it prints what it would do and changes nothing. Always run it first.Every script on the Azure Scripts page.

GitHub terms

TermWhat it meansWhere you see it
Repository (repo)A project folder whose history GitHub remembers.Your team's repo.
BranchA separate line of work in a repo. main is the main one; deployments here run from it.main, sprint-1.
GitHub ActionsGitHub's built-in robot. It runs tasks you describe whenever something happens in the repo, such as a push.The Actions tab.
WorkflowOne automated recipe, written as a file in .github/workflows/. A repo can have several.ci.yml, deploy-backend.yml
TriggerThe event that starts a workflow: a push, a pull request, or a button click.The on: section.
JobA group of steps that run together on one fresh computer. Separate jobs run side by side.frontend, backend
StepOne thing a job does: run a command, or use a ready-made action. Steps run in order and stop at the first failure.Each line with - run: or - uses:
RunnerThe temporary computer GitHub lends a job. It starts empty, so every job must download your code first.runs-on: ubuntu-latest
ActionA reusable step somebody else wrote, such as "download the code" or "deploy to Azure".uses: actions/checkout@v7
CI and CDContinuous integration: automatically check (lint, test, build) every change. Continuous delivery or deployment: automatically release a change that passed.ci.yml is CI; the deploy files are CD.
SecretA hidden value stored in a repo, such as a password or token. Once saved you can't read it again, and it never shows in logs. Use secrets for anything someone could misuse.Settings → Secrets and variables → Actions.
VariableA normal, visible setting that isn't sensitive, such as an app's name.AZURE_WEBAPP_NAME
Admin and Write rolesPermission levels. Write lets you push code. Admin can also change settings, add secrets, and delete the repo. Give Admin to as few people as possible (the principle of least privilege).Settings → Collaborators.
Run workflow buttonA trigger (workflow_dispatch) that lets you start a workflow by hand from the Actions tab, without pushing code.Right after setting up new Azure resources.

App and web terms

TermWhat it meansWhere you see it
Frontend and backendThe frontend is what runs in the visitor's browser (the map and forms). The backend runs on a server and holds the database logic and logins.frontend/ and backend/ folders.
APIThe set of web addresses the backend answers, which the frontend calls to get or save data./auth/login, /temperature/…
EndpointOne web address of an API that does one job, such as /forecast or /auth/login.GET /temperature/2020-07-01
HTTP methodThe kind of action in a request: GET reads, POST sends or creates, PUT and PATCH change, DELETE removes.api.get(...), api.post(...)
Status codeA three-digit number in every response. 2xx worked, 4xx means your request was wrong (401 not logged in, 404 not found), 5xx means the server had a problem (502 a server it depends on failed).Browser Network tab.
JSONThe text format most web APIs use to send data: objects in { }, lists in [ ], strings, numbers, true/false, and null. JSON.parse turns the text into a JavaScript object.[{ "lat": 38.9, "lon": -80.2, "tavg": 54.1 }]
RESTA common style of API: one URL per thing (/books/42), with the HTTP method saying what to do to it.The routes in backend/routes/.
API keyA secret string that identifies you to an API. Treat it like a password: keep it in .env on the server, never in the frontend or in git.process.env.WEATHER_API_KEY
Rate limitA cap on how many requests you may make in a period. Going over gives 429 Too Many Requests. Caching answers keeps you under it.The in-memory month cache in routes/stac.js.
Server-side request forgeryA weakness where a server can be tricked into requesting an address an attacker chose. Avoided by checking that any address from outside is on an expected host before fetching it.assertTrustedAssetUrl() in sign/sign.js.
.env fileA local file of settings and passwords for your own computer. It must never be committed; .gitignore keeps it out.backend/.env
Vite and buildVite turns your React source into plain files a browser can load (the "build"). Values like VITE_BACKEND_API_URL are copied into those files at build time, so they must be right when you build.npm run build
npm ci vs npm installnpm install can change package-lock.json; npm ci installs exactly what the lock file lists, so builds are repeatable. Workflows use npm ci.Every workflow.
LTS"Long-term support": the release of Node.js that is kept up with fixes for years. This course uses Node 24 LTS.node -v should start with v24.
CORSA browser rule: a page from one website may only call another website's API if that API says it is allowed. The backend allows only the frontend's address.FRONTEND_URL
JWT and cookieAfter login the backend gives the browser a signed token (a JWT) stored in a cookie, so you stay logged in. JWT_SECRET is the key it signs with; anyone who has it could forge logins.JWT_SECRET
HttpOnly, Secure, SameSiteCookie safety flags. Because the frontend and backend are on different sites in production, the cookie must be Secure; SameSite=None or the browser won't send it.NODE_ENV=production
Referer and Referrer-PolicyThe Referer header tells a site which page a request came from. A site's Referrer-Policy decides when the browser sends it. OpenStreetMap blocks map tiles that arrive without one.Troubleshooting: map shows "Access blocked".

Testing and quality terms

TermWhat it meansWhere you see it
LintAn automatic proofreader for code: it flags unused variables and likely mistakes without running the program.npm run lint
TestA small program that runs part of your app and checks it behaves as expected.npm test
CoverageThe share of your code that your tests actually ran. Low coverage means untested code.npm run test:coverage
Static analysisReading code without running it to find bugs, security problems, and messy code. SonarQube does this.The SonarQube guide.
Quality GateSonarQube's pass/fail verdict on recently changed code.SonarQube Overview page.
Access tokenA long random string that proves who you are to a service without sending a password. Treat it like a password.SONAR_TOKEN
