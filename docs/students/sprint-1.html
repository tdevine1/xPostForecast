Set up your tools, your team, and your first app

Sprint 1 gets everything ready. You install the tools, your team shares one GitHub repository, and you create a React app that you will grow all semester. Each step says who does it: every teammate, or one teammate (the Project Lead).

The xPostForecast repository is an example, not a template. Your team builds its own app on its own topic, in its own repository. The reference app's Sprint 1 branch shows what a finished Sprint 1 looks like. This guide uses VS Code's built-in Source Control, with no extra GitHub extensions. New words are explained in the Glossary.

Optional VS Code extension

Install from the Extensions sidebar (Ctrl+Shift+X): SQLTools by Matheus Teixeira (mtxr) and the SQLTools MySQL/MariaDB/TiDB driver (also by Matheus Teixeira). It isn't required, because in Sprint 2 you create your database from the Azure portal. It is handy for browsing your database from VS Code. If you use it, first read "Keep editor settings and passwords out of Git" in step 8.

Tell Git who you are (every teammate)

Set your name and WVU email so your commits show your name:

git config --global user.name "First Last"
git config --global user.email "abc123@mix.wvu.edu"

Check with git config --global --list.

2. Sign in to GitHub (every teammate)

  1. Go to github.com and log in with your WVU GitHub account.
  2. If your instructor created a class organization (for example WVU-CS330-2025), make sure you are a member.
  3. Accept any invitation to your organization or team repository once it is sent.
  4. You stay signed in through your browser when you clone from VS Code.

3. Create the team repository (one teammate: the Project Lead)

Goal: one shared repository that the whole team connects to from VS Code.

Create it

  1. On GitHub click + → New repository (top right). If you use a course organization, make sure you are inside it.
  2. Name it in the class format, for example cs330-2025-group07.
  3. Under Owner, choose your course organization, not your personal account.
  4. Visibility: Private, so only your team and instructor can see it.
  5. Tick Add a README file (it makes the first clone clean).
  6. Under .gitignore choose Node, which matches a React and Vite project.
  7. Click Create repository.

Add every teammate, with the least access they need

Go to your repository → Settings → Collaborators (or Collaborators and teams) → Add people, and invite every member of your team by GitHub username or WVU email. Each person must accept before they can push code.

Give teammates the Write role. Do not make everyone an Admin. This is the principle of least privilege: each person gets only the power the job needs. Write lets a teammate push branches and open pull requests. Admin can also change settings, add secrets, and delete the repository, so keep it with one person (the Project Lead, who created it). In Sprint 4 that person adds the deployment secrets; everyone else still deploys by pushing code.

Copy the clone address (every teammate)

On the repository's main page click the green Code button and copy the HTTPS address, for example https://github.com/WVU-CS330-2025/cs330-2025-group07.git. You paste it into VS Code in step 5.

4. A folder for your repos, and the terminal (every teammate)

  1. Open your home folder (for example C:/Users/YourName on Windows, or /home/yourname on Linux or macOS).
  2. Create a new folder named git. It will hold all your course repositories.
  3. Cloning in step 5 creates your project's folder inside it, named after the repository (for example cs330-2025-group07).
  4. When you clone, choose the git folder itself as the location. Don't create a project folder first, or you end up with one folder nested inside another.

Open a terminal in VS Code: menu View → Terminal, or press Ctrl + ` (the backtick key above Tab) on Windows and Linux, Cmd + ` on macOS. It opens at the bottom of VS Code in your workspace folder.

5. Clone the repository (every teammate)

  1. Open VS Code and click the Source Control icon in the left sidebar.
  2. Choose Clone Repository.
  3. Paste your repository's HTTPS address from step 3.
  4. Choose the git folder you made in step 4.
  5. When VS Code asks Open Cloned Repository?, click Open.

You should now see the repository in the Explorer sidebar and main in the bottom-left status bar.

6. Create the React app and commit it (one teammate: the Project Lead)

Why React and Vite

  • React is a JavaScript library for building user interfaces out of reusable components. Each page or widget is its own piece that is easy to maintain and extend.
  • Vite is a fast build tool and development server. It starts quickly and reloads the page as you save, and it replaced older tools such as Create React App and Webpack.
  • Many real-world web apps use this stack, so you learn practices you will meet on the job.

You start with a lightweight setup so later sprints can focus on logic, login, and data instead of setup trouble.

Create the project

In the VS Code terminal, in the top-level folder of your repository (the folder that contains README.md):

npm create vite@latest frontend -- --template react
cd frontend
npm install
npm install react-router-dom axios

If the tool asks whether to install and start the app now, either answer is fine; if the dev server starts, stop it with Ctrl+C. Keep the app directly in frontend, not in a deeper folder such as frontend/app: later sprints and the Sprint 4 deployment expect the frontend and backend folders side by side at the top of the repository.

If you get "...ps1 cannot be loaded because running scripts is disabled on this system", that is a Windows setting. Follow the fix at the end of this guide, then run the commands again.

Add a starter page to test the setup

Replace the frontend/src/App.jsx that Vite created with this simple page:

import React from 'react';

function App() {
  return (
    <div style={{ textAlign: 'center', marginTop: '50px' }}>
      <h1>CS330 Project Baseline</h1>
      <p>Your Vite + React app is running correctly!</p>
    </div>
  );
}

export default App;

Save it and run npm run dev. If the browser shows CS330 Project Baseline, everything works.

Commit the baseline with Source Control

  1. Click the Source Control icon. All the new files are listed under Changes.
  2. Click the + next to Changes to stage all changes.
  3. Type the message feat: initial Vite + React project baseline.
  4. Click Commit (the check mark above the message box).
  5. Click Sync Changes to push the commit to main on GitHub.

You have committed the baseline to main using VS Code's built-in Source Control.

7. Make a change with a branch and a pull request (every teammate)

Every teammate makes one small contribution. This proves that everyone can commit and open a pull request.

  1. Click the branch name in the lower-left corner → Create new branch, for example feature/<wvu-id>-intro.
  2. Make a small change, such as adding your name to the README or a test comment in src/App.jsx.
  3. In Source Control, stage the change with +, type a short message such as docs: add name to README, and click Commit.
  4. Click Publish Branch (or Sync Changes) to push your branch to GitHub.
  5. On GitHub, open a pull request (PR) from your branch into main.
  6. A different teammate reviews it and merges it when it looks good.

Why pull requests?

  • They keep main stable and free of unfinished or broken code.
  • Teammates can review and discuss a change before it is merged.
  • Each person's contribution shows up in the project history.
  • They prevent accidental overwrites, because changes arrive by merging instead of direct pushes.

Each teammate should end with one merged PR that shows their name in the commit history.

8. The .env file (every teammate)

A .env file holds settings such as your backend's address. That keeps values out of your code and keeps secrets out of GitHub.

Create it

  1. In VS Code open the frontend folder.
  2. In the Explorer click the New File icon and name the file .env.
  3. Add this line, which is the address your backend will use starting in Sprint 2, and save: 
    VITE_BACKEND_API_URL=http://localhost:5175
  4. Make sure .env is in your .gitignore. The Node .gitignore you chose in step 3 already ignores it (Vite's own frontend/.gitignore does not). To check, open Source Control: .env must not appear under Changes.

The example file

The Project Lead also creates and commits frontend/.env.example, with the same New File steps and this content. It tells teammates which values they need, without any secrets: 

# Example environment configuration
VITE_BACKEND_API_URL=http://localhost:5175

Each teammate has their own local .env, and .env.example is committed.

Keep editor settings and passwords out of Git

SQLTools (optional) saves every database connection in .vscode/settings.json inside your project. If a connection's Password mode is "Save as plaintext in settings", your database password is written there in plain text. The Node .gitignore does not ignore the .vscode folder, so one "Stage All Changes" would upload the password to GitHub, where it stays in the history even after you delete the file. This exact mistake happened in this course's own reference repository.

Two habits prevent it:

  • If you create a SQLTools connection in Sprint 2, set Password mode to SQLTools Driver Credentials (the default, which keeps the password in VS Code's secure storage) or Ask on connect. Never choose "Save as plaintext in settings".
  • The Project Lead opens .gitignore at the top of the repository, adds these lines at the end, and commits:
.vscode/*
!.vscode/extensions.json
*.PublishSettings

The first line ignores everything in .vscode. The second still allows extensions.json, a file your team can commit to recommend extensions such as SQLTools. The third ignores Azure publish profiles, which you download in Sprint 4 and which work like a password.

If a password is ever pushed, treat it as public. Change it in Azure first, then remove the file from the repository.

9. Run the app (every teammate)

From the frontend folder:

npm install
npm run dev

Open the address it prints (usually http://localhost:5173) to see your app. Stop it any time with Ctrl+C.

Fixing the "running scripts is disabled" error (Windows)

On Windows the VS Code terminal is PowerShell. npm comes with a small PowerShell script, npm.ps1, and Windows blocks PowerShell scripts until you allow them. So your first npm command (often npm -v or npm install) can fail with "npm.ps1 cannot be loaded because running scripts is disabled on this system." Try these in order. Most students need only Fix 1. macOS and Linux don't have this setting.

Fix 1: allow scripts for your own account (no administrator needed)

  1. In the VS Code terminal run: Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
  2. If PowerShell asks you to confirm, type Y and press Enter.
  3. Close the terminal (trash-can icon), open a new one (Ctrl+`), and run npm -v again.

RemoteSigned lets scripts already on your computer run, but still blocks unsigned scripts downloaded from the internet. -Scope CurrentUser changes the setting only for your own Windows account, which is why no administrator rights are needed.

Fix 2: if PowerShell says the setting is "overridden"

Run Get-ExecutionPolicy -List. If MachinePolicy or UserPolicy shows anything other than Undefined, an administrator set the policy (common on lab and work computers) and you can't change it yourself: use Fix 3. If only Process shows a value, close the terminal, open a new one, and try again.

Fix 3: use Command Prompt instead of PowerShell

  1. In VS Code press Ctrl+Shift+P and run Terminal: Select Default Profile.
  2. Choose Command Prompt (or Git Bash, which comes with Git).
  3. Open a new terminal. npm now works, because Command Prompt doesn't use PowerShell's script setting.

For a single command you can stay in PowerShell and type npm.cmd instead of npm, for example npm.cmd install.

Fix 4: allow scripts for the whole computer (administrator)

Use this only if the fixes above failed and the computer is your own.

  1. Close VS Code.
  2. Open the Start menu, type PowerShell, right-click Windows PowerShell, and choose Run as administrator. Click Yes.
  3. Run Set-ExecutionPolicy -ExecutionPolicy RemoteSigned and type Y.
  4. Close the window, reopen VS Code, and run npm -v in a new terminal.
Don't set the policy to Unrestricted or Bypass to make the error go away. Those let any script run, including ones downloaded from the internet.

Checklist

  • Git, Node.js 24, and VS Code are installed, and git config has your name and WVU email.
  • The team repository is private, in the course organization, with a Node .gitignore.
  • Every teammate is a collaborator with Write access, and only the Project Lead is Admin.
  • Everyone cloned the repository into their git folder.
  • The React app is in frontend/, shows "CS330 Project Baseline", and is committed to main.
  • Every teammate has one merged pull request.
  • Everyone has a local frontend/.env (not committed), and .env.example is committed.
  • .gitignore ignores .vscode/* (except extensions.json) and *.PublishSettings.
